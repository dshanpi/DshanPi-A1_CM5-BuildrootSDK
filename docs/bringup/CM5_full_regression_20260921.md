## 自动曝光与切流修正（继续实测）

IQ 中发现 `sw_aeT_opt_mode=RK_AIQ_OP_MODE_MANUAL`，线性曝光固定40ms、
模拟增益9.5倍，与三路1985行/增益寄存器152吻合。只将模式改为 AUTO，
板端实测增益变为192（现有自动路由上限12倍），其他 IQ 参数未改。
当前场景高反差且暗部仍黑，不能据此宣称画质标定完成。

切流问题进一步复现：逐路60帧拍照后再同时预览，三个虚拟 ISP 的
RAWAE/RAWAWB/RAWHIST 均 OFF，视频仍25fps，AIQ 报 meas_type=0。
试验性补丁0005加入 `RKAIQ_REINIT_ON_STOP=1` 开关，单路收到停止事件后
销毁并重新 init/prepare 该路 AIQ 上下文；默认不开启，不修改其他板行为。
这避免复用已失效的上下文状态，但尚不是底层库缓存问题的完整修复。

重编译3A服务后，在板端 /tmp 运行试验版，原 /usr/bin 二进制未替换：

- 三轮三路同时开停，共9次采集全部退出0；RAWAE/RAWAWB/RAWHIST持续ON，
  检查时 ErrCnt=0、frameloss=0，试验服务日志无 aec_stats_valid=false。
- 保持m00/m01预览，单独将m02开停三次，全部成功，另两路统计持续ON。
- 当前保留三路试验预览；未重刷。重启后会回到原3A服务，试验开关不自动持久化。

复现用法（先停止所有视频流和旧3A服务，不能同时启动两个3A服务）：

```sh
RKAIQ_REINIT_ON_STOP=1 /path/to/rebuilt/rkaiq_3A_server
```

仍需冷启动、快速连续切流、长时间内存观察和真实光照变化测试；暂不默认启用此开关。
板端原 IQ 已备份，可恢复；本次只更新在用 IQ 和试验进程，不代表已生成新系统镜像。

### 录音结论修正

此前使用 Left Right 采样，不能据右路底噪直接判定右路硬件损坏。
按用户先前提供的设置，`ADC Data Select=Left Left` 后两个PCM声道采样一致，
播放期间都由约-56升到-46dBFS。该配置是单麦克风复制到双声道，不是真正立体声。
主观讲话可懂度和实际收音电平仍需验证；本轮结束恢复测试前ALSA设置。
